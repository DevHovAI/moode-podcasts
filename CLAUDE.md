# moode-podcasts

Follow the `repo-flow` skill for anything involving git, GitHub, commits,
branches, pull requests, releases or publishing. Its hard rules apply here.

## The short version

- **No commit trailers.** No `Co-Authored-By`, no session link.
- **Author is** `DevHovAI <264851053+DevHovAI@users.noreply.github.com>`.
- **Never commit to `main`** — branch and pull request, always.
- **`just check` must be green before a push**, `just privacy` too.
- **Never `dnf` or `rpm-ostree install`** — the host is immutable on purpose.

## Language

Code comments and docstrings in this project are German and stay that way.
Everything outward-facing — commits, README, changelog, issues, pull
requests, release notes — is English.

## Project specifics

- **Standard library only** at runtime. The target is a Raspberry Pi with
  moOde; nothing gets pip-installed there. Pillow is used if present (it is
  on moOde), never required.
- **moOde is not modified.** Integration happens only through playlist files
  and covers, in the format `getPlaylistContents()` in moOde's
  `/var/www/command/playlist.php` reads. Check that function after moOde
  releases before changing the playlist format.
- **Never touch playlists we did not create** — names of our own are kept in
  `feeds.json`.
- `paths.py` reads the environment on every call so tests can redirect it;
  do not turn the paths into module constants.
- Write requests need the `X-Moode-Podcasts: 1` header (cheap CSRF guard).
- Tests never touch the network (`conftest.py`); `net.fetch` is replaced.
- The recommendation list is generated by `tools/build_recommendations.py`,
  which verifies every feed. Edit `PICKS` there, not the JSON by hand.
