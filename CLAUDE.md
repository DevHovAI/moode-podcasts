## Project specifics

- **Standard library only** at runtime. The target is a Raspberry Pi with
  moOde; nothing gets pip-installed there. Pillow is used if present (it is
  on moOde), never required.
- **moOde is not modified** (since 0.3). We only talk to MPD and read moOde's
  `cfg_radio`. `deploy/cleanup_v02.py` removes what 0.1/0.2 changed; keep it
  idempotent and byte-exact.
- MPD's queue is the queue: insert after the current song, never clear it.
- MPD 0.24 filters have **no OR** and fold case only for ASCII: see
  `library._find_artist` and the search variants; the fake MPD in
  `tests/conftest.py` rejects OR like the real one.
- The UI is plain ES modules in `static/` (no build step); `web.static_file`
  serves only files that exist there. Settings (theme, home blocks) are shared
  via `settings.json` and validated in `settings.clean`.
- Resume: MPD answers "Not seekable" right after starting a stream, so
  `Player._seek_when_ready` retries. Far seeks are slow with moOde's `mad`
  decoder — never "fix" that by changing moOde's MPD config.
- Never store position 0 as progress (MPD reports 0 after stop).
- `paths.py` reads the environment on every call so tests can redirect it.
- Write requests need the `X-Moode-Podcasts: 1` header (cheap CSRF guard).
- Tests never touch the network (`conftest.py`); MPD is faked over a socket.
- Keep image work cheap (`images.cached`, one conversion at a time): a Pi with
  a weak power supply resets under sustained full load.
- The recommendation list is generated by `tools/build_recommendations.py`,
  which verifies every feed. Edit `PICKS` there, not the JSON by hand.
- To look at the UI, drive headless Firefox over Marionette and wait a few
  seconds before the screenshot; a plain `firefox --screenshot` fires before
  the page has fetched its data.
